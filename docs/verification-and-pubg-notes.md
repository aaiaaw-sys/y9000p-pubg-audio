# 验证 Microsoft LEQ 与 PUBG 使用效果

## 三种证据不能混用

| 层级 | 可以说明什么 | 不能说明什么 |
|---|---|---|
| 注册表配置与 readback | child/参数已写入；OEM 绑定没有被脚本改动 | WM DSP 已运行、所有 OEM APO 同时处理每个 sample |
| audiodg 模块或初始化日志 | 某库/实例被加载或初始化 | 每个效果启用，或 PUBG 主观体验改善 |
| 可重复 A/B 与实际体验 | 目标设备上声音随开关有变化，用户更适应哪种配置 | 单凭主观体验精确定位整个音频 graph |

原案例模块枚举被访问控制拒绝，未突破权限取得完整 graph。使用者确认 LEQ 实际有效；没有量化响度曲线、脚步辨识率或距离判断测量。`ProcessingVerified=False` 是工具没有做音频测量的明确标记，不等于已经证明无效。

## 每台新设备的验收

1. 安装前保留普通播放正常、OEM 控制正常的参考。
2. 配置后手动重启，再确认 EarPods 左右声道、音量、麦克风/通讯使用没有明显异常。
3. 状态检查核实 child 和 enable/release，核对 release 档位；确认设备没有重新枚举为另一个 GUID。
4. 先旁路 EQ/VST，固定 Windows 和游戏音量、输出设备、空间音效/HRTF 等其它条件。
5. 用同一段含安静细节与大动态的素材比较 ON/OFF。关闭/重开播放应用，必要时重启 Windows，避免把旧 graph 的缓存当作开关无效。
6. 在 PUBG 中用尽可能相同场景比较脚步可听性、近远枪声、方向与距离判断。记录听感取舍；“声音更大”不自动等于定位更准。
7. 检查 Nahimic/Realtek 控制是否仍能产生原本的行为。记录任何 Elevoc/OEM 异常，不能仅靠 CLSID 仍在就宣布功能完整。
8. 再次重启确认持久性。

若无声、爆音、属性页崩溃或明显异常，使用本次备份做逐值 Restore，然后手动重启。若只是没有可重复变化，也先撤销本次试验并反馈，不叠加 context、APO 或未知参数。
